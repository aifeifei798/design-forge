# audit：审查与重做

两条独立入口，都必须由用户点名才进入（"审查一下这个页面" / "重做这个页面"）。

## 审查（只报告，不改代码）

### 步骤

1. 收集：`forge.mjs <目标> --json` 先跑静态档；能渲染且用户同意时加 `--render`。
2. 人工过一遍下面四张表（检查器抓不到的）。
3. 出报告：按 Floor / Reflex / Finish 分档，每条带位置，给改法一句话。

### 报告格式

```markdown
# <页面名> 审查

**结论**：<一句话：能不能发，最大问题是什么>

## Floor（必须修）
- `hero.css:12` 首屏 100vw，1440 宽度出现横向滚动条 → 改 `w-full`
- `index.html:44` 三张卡片里写了"服务 500+ 客户"，无出处 → 删除或换成真实数字

## Reflex（建议修）
- `index.html:62` eyebrow 组合 `uppercase tracking-widest text-xs` → 删掉那行
- `card.css:8` `.card .inner-card` 嵌套卡片 → 内层去边框

## Finish（记录）
- 首屏 1280×800 内主 CTA 可见：yes
- 一屏文字 ≤120 字：no（首屏约 190 字）
- 焦点顺序正常：yes
- 空态/加载/错误态：仅空态有文案，其余缺

## 建议的下一步
1. …
```

### 人工检查表

**感知层**
- 首屏 3 秒内能回答"这是什么、给谁、下一步做什么"？
- 有没有一个能记住的东西（照片/控件/数字）？没有就指出。
- 视觉重心是否唯一？区块之间是否有节奏（密—疏—密）？

**结构层**
- 区块顺序是否服务那个动作？动作是否出现在类别该在的位置？
- 有没有为了凑数存在的区块（团队、评价、FAQ 三连）？能不能删？
- 导航项 ≤6？页脚是否只是第二个导航？

**语言层**
- 标题是断言还是"欢迎来到"？
- 按钮写的是动作还是"提交"？
- 有没有编造的数字、客户、评价、认证？

**技术层**
- 图片有尺寸约束？布局有容器上限？
- 表单四态齐全？键盘能走通？
- 有没有 `!important`、魔法 `z-index`、写死的 px 宽度？

## 重做（保留内容与接线）

### 铁律

保留且必须逐项核对：**页面文案、链接 href、表单字段名与 action、事件 handler、路由、heading 层级、图片 alt**。只换视觉体系与布局。

### 步骤

1. `forge.mjs <目标> --json > .forge/before.json`，同时记录关键元素清单：

```js
// 记录一份"不能丢"的清单
[...document.querySelectorAll("a[href]")].map(a => a.getAttribute("href"))
[...document.querySelectorAll("input,select,textarea")].map(el => el.name)
[...document.querySelectorAll("h1,h2,h3")].map(h => h.textContent.trim())
```

2. 选新配方 → `tokens.mjs emit` → 替换旧 token（不要两套并存）。
3. 先首屏，再逐区块；每完成一个区块对比一次清单。
4. `forge.mjs <目标> --json > .forge/after.json`，比对 before/after 的链接、字段、heading 文本，一个都不能少。
5. 交付里给"改了什么 / 保留了什么的证据"。

### 三种重做的力度

| 说法 | 范围 |
|---|---|
| **只修毛病**（polish） | 只动 Floor/Reflex 命中的地方，不换体系 |
| **重做视觉**（restyle） | 换配方 + 排版 + 配色，布局基本不动 |
| **整体重做**（redesign） | 换体系 + 布局 + 信息层级，内容与接线不变 |

用户没说力度时按"重做视觉"做，并在开头说明；不要默认整体重做。

## 何时不接活

- 用户要求"把现有设计改得更好看"但没点名审查/重做 → 当成普通需求处理，不进 audit 流程。
- 目标页面有未提交的改动且用户没确认 → 先问，别覆盖别人的工作。
- 项目里 `DESIGN.md` 锁定体系 → 审查可以，重做必须用户明确解除锁定。
